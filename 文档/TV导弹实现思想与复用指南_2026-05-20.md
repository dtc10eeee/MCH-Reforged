# TV 导弹实现思想与复用指南（基于 MCH-Reforged）

目标：调研当前项目中 TV 弹（电视制导导弹 / 视角跟随导弹的指令制导）的实现思想，整理为可复用到其它游戏/引擎的“模块划分 + 数据流 + 失败模式”设计文档。

说明：本文强调玩法与系统设计，不要求复用 MCH 的代码结构；代码链接仅用于核对“它确实这么做”。

---

## 1. TV 弹在 MCH-Reforged 里是什么

TV 弹在当前项目中对应武器类型 `tvmissile`，由 `MCH_WeaponTvMissile` 发射 `MCH_EntityTvMissile`。

它有两个运行模式（武器模式，不是弹体模式）：

- **Mode 0：TV guidance（电视制导）**
  - 玩法：发射后进入“导弹相机视角”，玩家用视角方向/输入实时指挥导弹飞行。
  - 技术：导弹每 tick 读取“控制者（玩家/炮手）的 yaw/pitch”，把自身速度向量与朝向强行对齐到该视角方向。

- **Mode 1：TA / Laser guidance（末端攻击/激光点制导）**
  - 玩法：仍然使用 TV 弹这类弹体，但制导目标改为“激光点/目标点”（类似瞄准吊舱）。
  - 技术：客户端持续发布激光点状态到服务端，导弹每 tick 读取服务端存储的激光点坐标，并使用“导弹通用 guidanceToPos”去追。

入口文件：
- 武器：`MCH_WeaponTvMissile` [MCH_WeaponTvMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponTvMissile.java)
- 弹体：`MCH_EntityTvMissile` [MCH_EntityTvMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityTvMissile.java)
- 导弹相机与裁剪：`MCH_EntityAircraft.updateCamera` [MCH_EntityAircraft.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/aircraft/MCH_EntityAircraft.java#L5243-L5255)
- HUD 支持：`TVM_PosX/Y/Z/TVM_Diff` [MCH_HudItem.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/hud/MCH_HudItem.java#L516-L531)

## 2. 玩法目标（可迁移到其它游戏）

TV 弹的核心体验不是“更强的自动制导”，而是：

- **把“精确制导”变成一段短时的操作挑战**：你要稳住视角、修正偏差、避免撞地/撞障碍。
- **用相机切换强化代入感**：发射者视角 → 导弹前视相机 → 命中/失控后返回载具。
- **让载具玩法更丰富**：单人也能做“侦察-指示-打点”；多人时，炮手可以专职引导。

因此可移植的重点是“交互链路”和“失败反馈”，不必拘泥于导弹动力学的真实性。

---

## 3. 总体架构：三段链路

把系统拆成三块最容易移植：

1) **弹体（Missile Entity）**
  - 负责：物理/碰撞/爆炸/寿命
  - 负责：在“targeting=true”时执行制导逻辑（TV 或 Laser）
  - 不负责：UI、输入采集、摄像机渲染

2) **控制者（Controller）**
  - 可能是玩家、炮手 AI、或者其它“控制代理”
  - 输出：每 tick 的“控制方向”（yaw/pitch 或 forward vector），以及可选的“激光点”

3) **观测/相机（Camera/HUD）**
  - 决定当前画面是否切到导弹相机
  - 决定 zoom、夜视/热成像、HUD 文本与刻度

MCH 的实现对应关系：
- 弹体：`MCH_EntityTvMissile`
- 控制者：`shootingEntity`（玩家/炮手），以及其 `rotationYaw/rotationPitch`
- 相机：`MCH_EntityAircraft.camera`，当 `TVmissile != null` 时相机位置绑定到导弹

## 4. 数据流：发射 → 绑定 → 视角切换 → 持续制导 → 退出

### 4.1 发射端写入“运行模式”

武器发射时用 `option1` 把模式塞给服务端：

- `mode=0` -> TV guidance
- `mode=1` -> terminal attack (laser / line command)

并把结果写入弹体：
- `e.setTVMissile(isTVGuided)`（注意是“运行模式”，不是武器 info 的静态属性）

见 [MCH_WeaponTvMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponTvMissile.java#L129-L146)

### 4.2 绑定关系：Aircraft ↔ 当前 TV missile

为了实现“相机跟随导弹”，载具会记住当前 TV missile：
- `aircraft.setTVMissile(lastShotTvMissile)`

见 [MCH_WeaponTvMissile.update](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponTvMissile.java#L81-L96)

同时服务端会在发射初期广播一个通知包，让所有客户端知道“哪个载具对应哪枚 TV 弹”（用于渲染/相机一致性）：
- `MCH_PacketNotifyTVMissileEntity.send(acId, missileId)`

见 [MCH_WeaponTvMissile.update](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponTvMissile.java#L81-L91) 与 [MCH_PacketNotifyTVMissileEntity.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/aircraft/MCH_PacketNotifyTVMissileEntity.java#L15-L20)

### 4.3 相机切换：updateCamera 把 camera.position 绑定到导弹

当 `aircraft.getTVMissile() != null`：
- 相机位置 = 导弹位置
- 相机 zoom 强制为 1（导弹相机默认无放大）
- 同时根据是否处于导弹相机模式，控制导弹尾烟粒子是否生成（避免影响画面）

见 [MCH_EntityAircraft.updateCamera](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/aircraft/MCH_EntityAircraft.java#L5243-L5255)

### 4.4 持续制导：弹体每 tick 读取“控制方向”

TV guidance（Mode 0）：
- 导弹每 tick 读取 `shootingEntity.rotationYaw/rotationPitch`
- 把自身 motion 向量直接设置为该方向 * acceleration
- 同步把自身 yaw/pitch 也设置为该方向

见 [MCH_EntityTvMissile.onUpdateMotion](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityTvMissile.java#L71-L83)

Laser / terminal（Mode 1）：
- 客户端通过 `MCH_LaserGuidanceSystem` 计算“激光点”（射线检测/可锁实体/可 jam）
- 把激光点（x,y,z + active）同步到服务端存储
- 导弹从服务端读取最新 laser state，若 active 且未被干扰，调用 `onLaserGuide(x,y,z)`

见：
- 激光点计算与发包 [MCH_LaserGuidanceSystem.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_LaserGuidanceSystem.java#L63-L164)
- 服务端接收 targeting（旧包）[PacketLaserGuidanceTargeting.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/network/packets/PacketLaserGuidanceTargeting.java#L49-L60)
- 服务端接收 laser state（带序列与 TTL）[PacketLaserStateSync.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/network/packets/PacketLaserStateSync.java#L61-L74)
- 服务端/客户端状态存储（TTL、乱序保护）[MCH_LaserStateStore.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_LaserStateStore.java#L16-L114)
- 导弹读取 laser state 并引导 [MCH_EntityTvMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityTvMissile.java#L100-L109)

### 4.5 退出条件：距离过远/控制者死亡/寿命结束

导弹会在以下情况下终止：
- 控制者不存在（shootingEntity==null）→ 服务端直接 `setDead()`
- 控制者与导弹距离过远（> 2000）→ `setDead()`
- 达到弹体通用寿命/碰撞爆炸

见 [MCH_EntityTvMissile.onUpdate](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityTvMissile.java#L44-L57)

## 5. 关键设计点（为什么这么做）

### 5.1 TV guidance 用“视角方向”而不是“输入量”

MCH 选择直接用 `rotationYaw/rotationPitch` 作为导弹方向：
- 优点：实现极简；不需要处理键盘/手柄输入映射；只要能控制视角就能控制导弹
- 优点：在不同载具/炮手/玩家之间复用一致接口
- 缺点：导弹“转弯能力”≈无限（实际上受 acceleration + 每 tick 强制 setMotion 的等效约束），不是真实飞控

移植建议：
- 如果你在其它游戏引擎更追求真实：可以改成“视角提供期望方向”，导弹用最大角速度/最大过载去追随该方向（更顺滑也更像飞行）

### 5.2 “绑定载具的当前 TV missile”是为了视角一致性

相机与 HUD 的切换不直接绑定到“最后发射的实体”，而是绑定到“载具记录的 TVmissile 引用”：
- 这样玩家从 seat/载具角度看，TV 弹相机是载具的一个“子系统”，更稳定
- 同时也能在服务端广播绑定关系，让其他客户端渲染一致

### 5.3 终端激光模式复用同一弹体，降低内容成本

同一个 `tvmissile` 弹体既可以 TV 指令制导，也可以激光点末制导：
- 内容制作上只要做一套弹体模型/爆炸/数值
- 玩法上通过“模式切换”扩展出两种风格（TV 操作 vs 激光瞄准）

见模式区分注释 [MCH_WeaponTvMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponTvMissile.java#L133-L139)

## 6. HUD / 观测层：TV 弹需要什么信息

MCH HUD 暴露了：
- TV 导弹坐标 `TVM_PosX/Y/Z`
- TV 导弹与载具距离 `TVM_Diff`

见 [MCH_HudItem.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/hud/MCH_HudItem.java#L516-L531)

移植建议（其它游戏）：
- 最小 HUD：十字准星 + 距离/高度 + “返回载具提示”
- 可选 HUD：姿态指示（pitch/roll）、速度标尺、地面碰撞预警（拉起提示）

## 7. 网络与安全：把“可被作弊的输入”限制在合理范围

MCH 对 “Laser state” 同步做了两件重要的安全设计：

- **ownerId 不信任客户端**：服务端使用 packet sender 的 entityId 作为 owner
- **sequence 乱序丢弃 + TTL 过期**：避免网络延迟导致旧状态覆盖新状态；避免玩家断线后状态永远存在

见：
- ownerId 重写 [PacketLaserStateSync.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/network/packets/PacketLaserStateSync.java#L69-L74)
- TTL/sequence [MCH_LaserStateStore.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_LaserStateStore.java#L39-L114)

移植建议（其它游戏/引擎）：
- TV guidance 若走网络同步，建议传“期望方向”而不是直接传“导弹位置/速度”
- 限制更新频率（例如 10~30Hz），并对输入做平滑与最大角速度限制
- 当控制者死亡/切换席位/断线时，服务端要立刻终止或降级导弹制导（否则会出现无人机式外挂）

## 8. 干扰与对抗（玩法扩展点）

MCH 在激光制导上引入“光电干扰”概念：
- 如果激光点附近存在具备 `hasPhotoelectricJammer` 的载具或释放了特定 flare（type=10），则认为激光点被 jam，导弹不再追该点。

见 [MCH_EntityTvMissile.isLaserPointJammed](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityTvMissile.java#L114-L125)

移植建议：
- TV guidance 天生不怕这种“激光点干扰”，但怕“遮挡/烟幕/视线限制”
- 你可以把对抗做成：
  - 对 TV guidance：加入图像噪声/延迟/视野遮挡，迫使玩家减小操作精度
  - 对 laser mode：加入 jam/烟幕/反射面导致的漂移

## 9. 可复用到其它游戏的实现蓝图

### 9.1 最小可用 TV 导弹

模块：
- Missile: physics + collision + lifetime
- Controller: provides desiredDirection each tick
- Camera: follow missile; allow exit

伪代码（非 MCH 原代码）：

```text
if missile.active and missile.controllerAlive:
  desiredDir = controller.viewForward()
  missile.velocity = normalize(desiredDir) * missile.speed
  missile.orientation = lookRotation(desiredDir)
else:
  missile.selfDestructOrBallistic()
```

### 9.2 增强：支持“终端激光模式”

模块：
- LaserDesignator: compute target point (raycast) and publish to server
- LaserStateStore: per-owner state with TTL + sequence
- Missile: if mode==LASER, guidanceToPos(laserPoint)

伪代码（非 MCH 原代码）：

```text
laser = LaserStateStore.get(owner)
if laser.active and not jammed(laser.pos):
  missile.guidanceToPos(laser.pos)
else:
  missile.continueLastCommandOrBallistic()
```

## 10. 失败模式清单（移植时要主动设计）

- 视角切不回来（必须有强制退出键/超时）
- 控制者死亡/断线导致导弹“永远在飞”（必须 server-side 终止）
- 网络延迟导致导弹抖动（必须平滑、限制角速度）
- 相机跟随时渲染性能崩（需要 LOD/粒子降级；MCH 就在导弹相机模式下禁用尾烟粒子）
- 激光点被遮挡/被 jam 时的反馈不清晰（需要 HUD 提示：LOCK LOST / JAMMED）
