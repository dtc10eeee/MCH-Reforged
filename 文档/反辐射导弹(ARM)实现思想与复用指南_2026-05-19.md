# 反辐射导弹（ARM）实现思想与复用指南（基于 MCH-Reforged）

目标：调研当前 MCH-Reforged 的反辐射导弹（Anti-Radiation Missile / ARM）设计与实现思路，整理成一份可迁移到其他 mod 的“数据流 + 状态机 + 目标选择 + 参数化”参考文档。

本文以“可复用思想”为主，不要求复制原项目的类名结构。

---

## 1. ARM 在当前项目里是什么

在 MCH-Reforged 中，ARM 不是独立武器类型，而是 **在导弹武器配置上开启 `AntiRadiationMissile=true` 后**，导弹的“目标选择/制导逻辑”切换为“寻辐射源”模式。

ARM 目前主要落在两类导弹实体上：

- 空空导弹实体：`MCH_EntityAAMissile`（AA ARM）
- 空地导弹实体：`MCH_EntityATMissile`（AT ARM，偏对地雷达载具/防空车一类）

共用的“扫描目标 + 选择辐射源 + HOJ 优先级”逻辑主要在基类：
- `MCH_EntityBaseBullet.scanForTargets()`（内部含 ARM 优先分支）

关键文件入口：
- ARM 配置项：`MCH_WeaponInfo` [MCH_WeaponInfo.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponInfo.java#L436-L463)
- ARM 武器发射端（AA/AT）：[MCH_WeaponAAMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponAAMissile.java) / [MCH_WeaponATMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponATMissile.java)
- ARM 导弹实体（状态机）：[MCH_EntityAAMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityAAMissile.java) / [MCH_EntityATMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityATMissile.java)

## 2. 配置项：ARM 行为如何参数化

ARM 的专用配置项在 `MCH_WeaponInfo`：

- `AntiRadiationMissile`：是否为反辐射导弹（ARM 总开关）
- `ArmEmitterLostGraceTick`：丢失辐射源后的宽限 tick（“刚丢失不立刻进入记忆/失锁”）
- `ArmMemoryTimeTick`：记忆制导持续 tick（在 last-known 坐标上继续飞）
- `ArmCruiseEnable / ArmCruiseStartDistance / ArmCruiseTerminalRadius / ArmCruiseTerminalHeight`：ARM 巡航段参数（让导弹中段更平直，末段才追高度）

## 3. “辐射源”在 MCH 里的定义（核心思想）

### 3.1 什么算“正在辐射”

ARM 不追所有实体，而是追“被认为正在辐射”的平台。判定在基类：

- `isArmEmitterRadiatingSource(MCH_EntityAircraft emitter)`

见 [MCH_EntityBaseBullet.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityBaseBullet.java#L1595-L1603)

判定逻辑（要点）：
- 目标必须是 `MCH_EntityAircraft`（项目里“飞机/坦克/车辆”都继承这个基类）
- `emitter.getAcInfo().hasRWR == true`（作为“具备电磁能力/可被动告警”的简化门槛）
- 目标必须“有人操作/有炮手”：`hasArmEmitterCrew(emitter)`（玩家或 Gunner）
- 满足下列之一即认为辐射：
  - `enableRadar && radarEnabledRuntime == true`（雷达开机发射）
  - `isECMJammerUsing() == true`（电子干扰机开机，也视作可 HOJ）

### 3.2 友军屏蔽（避免 ARM 把友军雷达当目标）

ARM 在“扫描候选辐射源”时，会屏蔽友军辐射源：

- `isFriendlyArmEmitterSource(emitter)`：按队伍判断
- 并且只对“有玩家或 Gunner 驾乘”的载具进行友军屏蔽（避免误判纯 AI/无乘员对象）

见 [MCH_EntityBaseBullet.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityBaseBullet.java#L1541-L1579)

移植建议：其他 mod 若没有“座位/乘员”概念，也可以直接用 `team/faction` + `owner` 做屏蔽。

## 4. ARM 的两条“目标来源”路径：宽频（自主寻的）与窄频（手动选源）

### 4.1 宽频（Wide Band）= 自主寻的

宽频模式的思想：发射后导弹自己扫整个 FOV 里的辐射源，挑选最优目标。

实现落点：
- 导弹实体 tick 中，ARM 分支会在没有目标或目标不再辐射时 **持续 scanForTargets（不受 scanInterval 门控）**：
  - `// ARM seeker reacquires radiation source continuously (not gated by scanInterval).`

见：
- AA ARM：[MCH_EntityAAMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityAAMissile.java#L195-L201)
- AT ARM：[MCH_EntityATMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityATMissile.java#L258-L264)

### 4.2 窄频（Narrow Band）= 手动选源/手动锁定后才能发射

窄频模式的思想：玩家在发射前先在“电磁告警/目标列表”里选定一个辐射源并锁定（trackingTargetId），发射时将该 emitterId 传给导弹作为初始目标提示（cueing）。

关键点有两个：

1) UI 侧提供 ARM 联系人列表与“选中/锁定 emitterId”
- `MCH_RenderRWR` 维护 `armBvrContactCache`（来自 RWR 威胁事件）
- 提供 `handleArmSelectKey` 选择候选源、`handleArmTrackToggleKey` 锁定/解锁
- 发射端通过 `getArmTrackingTargetId(ac)` 读取锁定目标 ID

见：
- `getArmTrackingTargetId` [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L3207-L3247)
- `refreshArmBvrContacts` [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L3001-L3075)

2) 发射端强制约束：窄频没锁定目标则拒绝发射
- AA：`MCH_WeaponAAMissile.shouldBlockShotByArmBandConstraint`
- AT：`MCH_WeaponATMissile.shouldBlockShotByArmBandConstraint`

见：
- AA：[MCH_WeaponAAMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponAAMissile.java#L211-L240)
- AT：[MCH_WeaponATMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponATMissile.java#L223-L241)

移植建议：窄频模式本质上就是“发射前必须有 cue”，可以用任何 UI/锁定方式实现（雷达警告列表、RWR 页面、ELINT 页面、手动选择附近辐射源等）。

## 5. ARM 目标选择算法（scanForTargets 的核心思想）

ARM 的“自主寻的”目标选择不只是最近距离，它综合考虑：

- 角度（相对于导弹当前速度方向的夹角）
- 距离（归一化后加权）
- HOJ（干扰机开机）优先级（直接“最高优先级”）
- 友军屏蔽
- 目标类型约束（AA ARM 只允许空中平台，AT ARM 只允许地面载具）

实现位置：
- `scanForTargets` 内 ARM 分支会计算 `closestArmScore`，选择 `closestArmTarget`
- HOJ：若 `ac.isECMJammerUsing()` 则 `armScore -= 180°`（直接压到最优）
- 最终如果存在 ARM 目标则 **强制覆盖**普通 chaff/普通目标选择：`ARM always prioritizes radiating emitters once detected.`

见：
- [MCH_EntityBaseBullet.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityBaseBullet.java#L2235-L2419)

移植建议：
- “角度优先”能避免导弹为了追一个侧后方辐射源做过大转向；
- HOJ 可视作单独权重项：当 jammer on 时，优先级极高，但准确性下降（见第 6 节）。

## 6. ARM 导弹实体状态机（HOMING / MEMORY / LOST）

AA 与 AT 的 ARM 状态机基本一致：

- `ARM_STATE_HOMING`：当前存在辐射源目标且正在辐射 → 直接追目标实体位置
- `ARM_STATE_MEMORY`：丢失辐射源后 → 在最后一次“看到辐射”时的坐标上继续飞（last-known）
- `ARM_STATE_LOST`：超过 grace+memory 时间仍未重新捕获辐射 → 清空目标，停止 ARM 逻辑（剩下就按惯性飞/自然碰撞）

关键字段（AA 为例）：
- `armLastRadiationSeenTick`：最后一次确认辐射的 tick
- `hasLastKnownTarget + lastTargetPosX/Y/Z`：最后一次辐射坐标记忆
- `armEmitterLostGraceTick + armMemoryTimeTick`：两段时间窗

见 AA ARM：
- [MCH_EntityAAMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityAAMissile.java#L166-L229)

记忆段逻辑特点：
- 记忆段 **使用“坐标”而不是“速度预测”**（只飞向 lastPos，不做 lead）
- 好处：实现简单且稳定；缺点：目标在关闭雷达后快速机动，会让末段偏差增大

移植建议：若你的 mod 更追求真实，可在 MEMORY 阶段加入速度预测（lastVel * t）或保留若干历史点做滤波。

## 7. HOJ（Home-on-Jam）与 CEP（精度惩罚）

当前实现把“干扰机开机”也视作可追的辐射源，并且赋予最高捕获优先级（见第 5 节），同时加入一个非常直观的代价：

- 当 `armHojCepActive == true`（目标是 jammer-on 平台）时，制导点在 X/Z 平面加入随机扰动：
  - `tx += (rand-0.5)*14`
  - `tz += (rand-0.5)*14`

见：
- AA：`guideArmToPosition` [MCH_EntityAAMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityAAMissile.java#L158-L164)
- AT：`guideAtToPosition` [MCH_EntityATMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityATMissile.java#L198-L227)

这相当于一个“CEP 增大”的模拟：HOJ 更容易捕获，但命中点更散。

移植建议：
- HOJ 可做成“锁定更快/更稳定 + 末段精度更差”的组合；
- CEP 可以改为随距离或时间变化（末段越近越小）以提升体验。

## 8. ARM 的 UI/交互设计：为什么依赖 RWR 威胁事件

MCH 的窄频 ARM 不是凭空“扫描全世界雷达”，它主要用 **RWR 威胁事件**作为“辐射源候选集合”的来源：

- `MCH_RWRThreatClientTracker.getEvents(aircraftId)` 给出最近的威胁事件
- ARM 从这些事件中过滤：
  - 排除导弹 emitter（`EMITTER_MISSILE`）
  - 排除自己、友军、己方发射导弹等
- 形成 `armBvrContactCache` 并设置 TTL（`radarContactHoldTick/2`）
- 候选列表按“跟踪/选中优先、威胁模式优先（STT>TRACK>SEARCH）、距离”排序

见：
- `refreshArmBvrContacts` [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L3001-L3129)
- `isArmContactAllowedForCurrentWeapon`（按导弹类型筛目标：AA 只看飞行器，AT 只看地面载具）[MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L3132-L3153)

移植建议：
- 如果其他 mod 没有 RWR 体系，可以用“雷达开机广播事件”“电磁发射源管理器”等替代；
- 关键是：窄频模式需要一个“可信候选集合”，避免 UI 列出一堆不相关对象。

## 9. 可移植实现蓝图（给另一个 mod 的建议）

### 9.1 最小可用 ARM（宽频）

数据结构：
- `EmitterState { id, pos, team, isRadiating, isJammerOn }`
- 导弹实体保存：
  - `lastRadiationTick`
  - `lastKnownPos`
  - `armState: HOMING/MEMORY/LOST`

导弹 tick：
1) 若 `target != null && target.isRadiating` → HOMING（制导到 target.pos）
2) 否则尝试 reacquire：扫描 FOV 内所有 radiating emitters，选最优（角度+距离+HOJ）
3) 若 reacquire 成功 → HOMING
4) 若失败：
   - 若 `now - lastRadiationTick <= grace+memory` → MEMORY（制导到 lastKnownPos）
   - 否则 → LOST（停止制导/转入惯性）

### 9.2 建议增强：窄频（带 UI 选源）

需要额外的“候选集合来源”：
- 来自 RWR/ESM 事件、或来自雷达开机广播、或来自“被玩家探测到的电磁源列表”

交互：
- `selectedEmitterId`（循环选择）
- `trackingEmitterId`（锁定/解锁）

发射约束：
- 窄频未锁定目标时拒绝发射（体验上更符合“窄频需要指示”）

### 9.3 建议增强：HOJ 精度惩罚

当目标是 jammer-on：
- 捕获优先级大幅提高
- 末段制导点加入随机扰动或噪声滤波

## 10. 常见坑点

- “辐射源判定”过严：当前实现要求 `hasRWR && has crew`，如果你的载具/炮台不是这个体系，ARM 可能永远抓不到目标。
- 友军屏蔽策略：若没有 team 系统，建议至少用 owner/faction 屏蔽，否则容易误伤队友雷达车。
- MEMORY 阶段不做速度预测：对高速目标可能偏差大；可自行增强。
- 窄频 UI 的候选来源：如果候选集合不可靠，玩家会觉得“锁不到/乱跳/列表为空”。
