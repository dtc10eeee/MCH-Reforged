## 1. 玩法思想：Gunner 在系统里的定位

MCH 的 Gunner 不是“独立战斗 AI（像怪物那样在地面走路射击）”，而是：

- 一个 **可生成/可移除的 AI 乘员实体**；
- 通过 `mountEntity()` 挂载到载具本体或某个 Seat；
- 在载具允许 Gunner 的前提下，Gunner 会：
  - 自动索敌、自动选武器、自动开火；
  - 若坐在 Pilot 位，还能 **代替玩家操纵载具移动**（坦克/直升机/飞机三套不同驾驶 AI）；
  - 自动释放反制（flare/chaff/ECM/APS），让载具有“自保能力”。

这套设计的核心价值是：
- 单人也能玩“多人载具”的火力配置（例如坦克车长位+炮手位）
- 服务器 PVE/PVP 都能通过 Profile 调控难度、阵营、行为风格
- 通过“愚蠢炮手（stupid gunner）”等手段让 AI 有可玩性和差异化，而不是纯外挂

## 2. 角色与类型：Gunner 会打谁

`MCH_EntityGunner` 内置 4 种目标类型（DataWatcher 同步）：

- `TARGET_MONSTER`：打怪与敌对 Gunner
- `TARGET_PLAYER`：PVP（需要队伍/阵营约束）
- `TARGET_AA_AMMO`：打来袭弹药（导弹/火箭/炸弹/marker 等）
- `TARGET_ENEMY`：综合敌对（玩家 + 友军阵营 Gunner + 中立生物等，按规则判定）

## 3. 生成与移除：怎么把 Gunner 放上去

### 3.1 道具右键放置（主要玩法入口）

`MCH_ItemSpawnGunner.onItemRightClick(...)` 实现了“看着座位/载具右键把 Gunner 放上去”的交互：

1) 从 Profile 或道具字段读取：
   - targetType、stupid、factionRole、mountSearchRange
   - 是否允许 mount 到 aircraft/seat、是否允许替换已有 Gunner
2) 玩家视线范围内（默认 5 格或 profile 指定）依次尝试命中：
   - 最近的 Gunner（用于右键移除）
   - Seat
   - Aircraft 主体（驾驶位）
3) 服务端创建 `MCH_EntityGunner`，设置：
   - `ownerUUID`（用于归属）
   - `teamName`（用于阵营/友军）
   - profile 行为参数（见第 4 节）
4) `world.spawnEntityInWorld(gunner)` 后 `gunner.mountEntity(mountTarget)`

见 [MCH_ItemSpawnGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_ItemSpawnGunner.java#L45-L186)

`MCH_CommandAddGunner` 提供了以半径扫描载具并为每个空 seat 挂 Gunner 的能力，并支持：
- 指定 friendly/player/aa/enemy

见 [MCH_CommandAddGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/command/MCH_CommandAddGunner.java#L42-L158)

### 4.2 Profile 能配置什么

`MCH_GunnerInfo` 支持的关键项：

  - `MountSearchRange`

  - `EnableShortBurst`（短点射）

- “愚蠢炮手”：
  - `StupidGunner`
  - `StupidGunnerChance` / `StupidGunnerChanceByRole`

## 5. 索敌：Gunner 怎么找目标

核心方法：`updateTargetForWeapon(ac, ws, pos)`，特点：

- 使用 `switchTargetCount` 做节流（常见为每 5 tick 重新选择一次，或在进入特定情形延长到 60 tick）
- 搜索范围受 targetType、载具类型（plane pilot 有扩展搜索半径）、profile 覆盖与 config 回退影响
- 对 AA 模式（TARGET_AA_AMMO）专门扫描导弹/火箭/炸弹等，并排除友军弹药
- 对普通 EntityLivingBase：
  - 先按 targetType 过滤（怪/玩家/敌对）
  - 再做视线 `canEntityBeSeen`
  - 再做俯仰限制 `checkPitch` 和 “扇区”限制 `isInAttackable`
  - plane pilot 会使用“bucket”评分来决定优先级（空中目标更注重 FOV 与距离分档，地面高价值目标加权）

见 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L804-L963)

移植建议：
- 把“索敌”拆成两层：候选筛选（范围/类型/友军）→ 可攻击判定（FOV/俯仰/视线/武器锁定能力）
- 把“目标选择节流”做成固定 tick（例如 5~10 tick），可大幅省 CPU

## 6. 武器控制：自动选武器、提前量与开火窗口

### 6.1 自动选武器（按上下文）

`updateWeaponRotation(ac)` 会在一定 tick 后切换武器：

- 若有目标：
  - 区分 airContext/groundContext
  - 用 `selectWeightedWeaponId(...)` 按权重挑选
  - profile 若提供 `AirWeaponPriority/GroundWeaponPriority` 则直接走“最高优先级武器”
- 若无目标：按 `getNextWeaponID` 轮询（较慢节奏）

见 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L2365-L2436)

### 6.2 提前量（Lead）与“愚蠢炮手”

`shotTarget(ac)` 在计算 yaw/pitch 时会对目标速度做提前量：

- tick 由距离与武器加速度估算（并对 HitBoxDelayTick 做修正）
- 对 airTarget 才更有必要，且可被 profile 关闭 `AllowLeadForAirTarget=false`
- stupidGunner 会禁用提前量并加入较大的随机散布

见 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L517-L557)

### 6.3 开火窗口（防止“瞬间甩枪”）

Gunner 不会每 tick 都直接把朝向 snap 到目标，而是：

- 先算目标 yaw/pitch
- 只有当当前 `rotationYaw/rotationPitch` 与目标差值小于 `shotWindow` 才允许开火
- plane/heli pilot 还会额外检查 `isPlaneFireWindowReady / isHeliFireWindowReady`（包括机头对准、视线、距离窗口）

见 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L544-L579) 与 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L2050-L2096)

### 6.4 导弹/制导武器接口（通过 option1/option2）

发射时通过 `MCH_WeaponParam` 传入：
- `prm.user = gunner`
- `prm.entity = aircraft`
- `option1`：对 seeker/AS 导弹等传 `targetEntityId`
- `option2`：对 AT 导弹传 mode

见 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L565-L577)

移植建议：
- 把武器调用统一成一个 `WeaponParam`（user、platform、targetId、mode、发射位置等）
- AI 层只负责填 param，不直接操作弹药实体

## 7. 驾驶 AI：当 Gunner 坐在 Pilot 位时

MCH 的重要玩法点是：Gunner 不仅能当炮手，还能当“AI 司机/AI 驾驶员”。

触发条件：
- Gunner 挂在载具主体（seat 1）或 seat 0 且允许 pilot
- `ac.isPilot(gunner)` 为 true

在 `onUpdate()` 内：
- tank → `updateTankDrive`
- heli → `updateHeliDrive`
- plane → `updatePlaneDrive`

见 [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L339-L363)

### 7.1 坦克（地面载具）驾驶思想

坦克驾驶的核心思想是：**始终输出“人类玩家能理解的方向盘/油门动作”**，并用少量行为层级把“导航、战斗、游走、防卡死”统一起来。

#### 7.1.1 输入与输出（可移植抽象）

- 输入（每 tick 可读）：
  - 自身位置/朝向/速度（至少平面 XZ）
  - 目标（可空）：目标位置、是否近距离、是否在前方扇区
  - 可选导航（可空）：导航目标点、是否强制导航优先
  - 简单环境信息：是否碰撞、前方是否高障碍、是否在水里/斜坡导致动不了
- 输出（每 tick 写给载具控制层）：
  - 加油门 / 减油门（或设定目标油门）
  - 左转 / 右转
  - 刹车
  - 可选：轻微“直接修正车体 yaw”（用于辅助转向稳定）

#### 7.1.2 行为层级（不引入额外参数）

MCH 的坦克驾驶大体是三层优先级：

1) **导航层（Navigate）**：如果存在“强导航优先”，就优先朝导航点走
2) **战斗层（Combat）**：否则如果有目标，就进入追击/绕圈/保持距离的战斗驾驶
3) **游走层（Wander）**：都没有就低速游走并周期性小转向

并且无论哪一层，都有一个更高优先级的“**安全层**”覆盖：
- 卡死检测 → 强制大角度脱困
- 障碍物检测 → 临时避障转向
- 速度过快且偏航误差大 → 先减速再转向（避免“推头直行”）

#### 7.1.3 典型动作细化（你需要移植的玩法感）

- 导航时：
  - 计算“目标 yaw”与“当前 yaw”差值
  - 若差值大：先减速，再转向
  - 若距离很近：减速并刹车，直到朝向也基本对齐
  - 过程中持续施加轻微 yaw 修正（让它像“司机一直修方向”）

- 战斗时：
  - 目标很近：进入“绕圈”而不是直接撞上去
  - 目标较远：保持带偏置的追击（不要直线追，避免过于机械）
  - 油门采用“脉冲式”（一段时间加速，一段时间滑行/减速），会让追击更像人在开车
  - 允许出现“周期性大转向动作”（像司机突然决定换角度包抄）

- 游走时：
  - 维持低速前进
  - 随机轻微左右摆动
  - 若长时间没移动则触发脱困（见下一节）

#### 7.1.4 防卡死/脱困（这是坦克 AI 是否好玩的关键）

MCH 在坦克上投入了大量“脱困”逻辑，核心不是精确物理，而是：

- 发现“车体位置几乎不变” + “有明显转向需求” → 判断可能卡住
- 触发一个短时的大角度转向（甚至原地打方向）来改变朝向
- 脱困后设一个冷却，避免每秒反复触发

**伪代码（非 MCH 原代码，仅表达思想）**：

```text
[TANK-PILOT-LOOP]
if destroyed or no fuel:
  brake, stop controls
  return

nav = readOptionalNavTarget()
target = readOptionalCombatTarget()

if nav.active and nav.preferNavigate:
  driveToward(nav.pos) with "slow down when yaw error is large"
else if target.exists:
  driveCombat(target) with "orbit when close + throttle pulse + small yaw bias"
else:
  driveWander() with "slow forward + periodic small turn"

if detectObstacleAhead():
  applyAvoidTurn()

if detectStuck():
  startLargeTurnEscape()
```

#### 7.1.5 运动“装填感”：周期性大转向 + 转向反馈（左右平衡）

你提到的两个“装填式运动特征”，MCH 确实做了，而且它们对“AI 看起来像人在开车”非常关键：

1) **周期性触发大幅度转向（large turn）**
- 在追击/战斗驾驶时，每隔一段时间会重置一个 combat cycle。
- cycle 重置时，会强制启动一次 “large turn”（例如 120~180 度量级），相当于 AI 司机突然决定“换一条包抄角度”，让追击轨迹不机械。
- 同一时间也会在“长时间没动”或“导航卡住”时触发 large turn，用同一套机制脱困。

对应行为可以从下列片段看出来：
- 战斗 cycle 触发 large turn：[MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L1075-L1138)
- noMove/导航卡住触发 large turn：[MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L1178-L1196)
- large turn 执行：每 tick 消耗 `largeTurnRemain` 并强制 moveLeft/moveRight：[MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L1220-L1234)

2) **左右转向“反馈平衡”（turn feedback）**
- MCH 统计一段采样窗口内“左转帧数”和“右转帧数”。
- 如果左转明显多于右转，就在接下来一段时间内“提高右转触发概率/抑制左转”（反之亦然）。
- 这会产生你说的现象：一段时间左转过多，下一段时间右转频率上升，整体轨迹更像“司机修方向”，也更不容易一直绕一个方向打转。

对应实现：
- 采样与反馈判定（每 90 tick 一次）：[MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L1251-L1271)
- 战斗与游走阶段应用 turn feedback（以概率强制偏向某一侧）：[MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L1103-L1114), [MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L1154-L1162)
- feedback tick 递减归零：[MCH_EntityGunner.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/mob/MCH_EntityGunner.java#L2798-L2804)

**伪代码（非 MCH 原代码，仅表达“装填感”思想）**：

```text
[TURN-FEEDBACK]
if turningLeft this tick:  leftCount++
if turningRight this tick: rightCount++
sampleTicks++

if sampleTicks reaches window:
  diff = leftCount - rightCount
  if diff is large positive: feedbackDir = RIGHT, feedbackTime = some duration
  if diff is large negative: feedbackDir = LEFT,  feedbackTime = some duration
  reset sampleTicks/leftCount/rightCount

if feedbackTime > 0:
  feedbackTime--
  with high probability, enforce feedbackDir turn input (and suppress the other side sometimes)

[LARGE-TURN]
if startOfCombatCycle or stuckDetected:
  largeTurnRemain = bigAngle
  largeTurnDir = random LEFT/RIGHT (or choose by nav yaw error sign)

if largeTurnRemain > 0:
  apply a turn step toward largeTurnDir
  largeTurnRemain -= step
  force throttleUp (keep moving during the maneuver)
```

移植建议：不需要把这些做成可配置参数。固定窗口（例如 1~2 秒采样）与固定反馈时长（例如 2~3 秒）就足够形成“像人类司机”的节奏。

### 7.2 直升机驾驶思想

直升机驾驶的核心思想是：**用 AGL（距地高度）作为主控制量**，用少量状态机管理“巡航→对准→攻击→脱离”的节奏，避免直升机 AI 变成“永远顶着目标直冲”或“无限爬升飘天”。

#### 7.2.1 状态机节奏（玩法感）

- CRUISE（巡航）
  - 保持一个“舒服的 AGL 高度”
  - 以小幅度巡逻转向，像在搜索
  - 没目标就不强行机动，也不射击

- FOCUS（对准）
  - 有目标后进入
  - 强化 yaw 对准目标，但暂时不允许射击（给玩家一种“AI 先压准再打”的可信感）
  - 提高前进/油门，让它尽快进入合适位置

- ATTACK（攻击）
  - 允许射击
  - 仍以 AGL 高度保持为主，避免一边射击一边飘到天上或撞地
  - yaw 持续指向目标，pitch 调整为“略带俯仰的稳定姿态”

- DISENGAGE（脱离）
  - 当攻击持续一段时间，或目标丢失，进入脱离
  - 朝“远离目标最后位置”的方向飞一段时间
  - 前半段更积极（像甩开），后半段收敛回巡航

#### 7.2.2 两个关键技巧：避障与导航高度

1) **紧急避障覆盖**
- 每 tick 扫描近距离危险实体（载具、重要单位）
- 若发现危险：强制把 desiredYaw 改为“远离威胁”的方向，并降低 pitch，快速拉开
- 同时禁止射击（避免一边射击一边撞上去）

2) **导航时不要追 waypoint 的绝对 Y**
- Waypoint 通常是“地面点”，直接追它的绝对高度会导致起飞/低空阶段频繁上下振荡
- 更好的方式是：导航时仍然用“目标 AGL”做高度控制（保持一个相对地面高度），只用 waypoint 的 XZ 方向做航向

#### 7.2.3 控制输出（不要引入额外参数）

直升机控制可以只保留：
- desiredYaw（朝向目标或导航方向）
- desiredPitch（用来“往前飞/爬升/俯冲”的抽象控制量）
- throttleUp / throttleDown（维持高度与速度）
- moveLeft / moveRight（辅助 yaw 输入）

**伪代码（非 MCH 原代码，仅表达思想）**：

```text
[HELI-PILOT-LOOP]
if destroyed or no fuel:
  stop controls, forbid fire
  return

state = updateHeliStateMachine(targetExists, stateTimer)

altitudeAgl = computeHeightAboveGround()

desiredYaw = (target ? yawTo(target) : yawPatrol())
desiredPitch = pitchFromStateAndAltitude(state, altitudeAgl)

if nav.active and nav.preferNavigate:
  desiredYaw = yawTo(nav.posXZ)
  desiredPitch = keepAglPitch(altitudeAgl)   // do not chase nav.y directly
  forbid fire

if emergencyObstacleNear():
  desiredYaw = yawAwayFromObstacle()
  desiredPitch = safePitch()
  forbid fire

applyYawSmoothingToward(desiredYaw)
applyPitchSmoothingToward(desiredPitch)
applyThrottleToHoldAgl(altitudeAgl)
```

#### 7.2.4 接战/脱战细化：FOCUS→ATTACK→DISENGAGE 的“战术节奏”

直升机最容易写成“发现目标就永远追着打”。MCH 的玩法节奏更像“短接战、多次复攻”：

- 接战门槛（FOCUS）
  - 发现目标后先进入 FOCUS，**明确禁止开火**（`heliAllowFire=false`）
  - FOCUS 期间主要做两件事：
    - 对准目标 yaw（保存 lastTargetX/Z 以便脱战用）
    - 把油门强行顶上去（即使高度还没完全对上），快速进入攻击位
  - 直到满足“对准窗口 ready”或超时，才进入 ATTACK

- 攻击段（ATTACK）
  - `heliAllowFire=true`
  - yaw 继续锁定目标
  - pitch 主要用于控制“前进速度”和“高度误差补偿”（用 AGL 偏差映射到 pitch）
  - 高度控制仍以 AGL 为主：低于巡航高度则加油门，高于则减油门

- 脱战段（DISENGAGE）
  - `heliAllowFire=false`
  - yaw 改为“远离 lastTargetX/Z 的方向”
  - pitch 在脱战前半段给一个更激进的姿态（更像快速拉开），后半段回到平稳姿态
  - 高度目标会略高于巡航高度（避免低空拉开撞地）
  - 脱战持续到计时结束后再回 CRUISE（并随机一个新的巡航高度）

### 7.3 飞机驾驶思想

固定翼驾驶的核心思想是：**用“节奏化状态机 + 返航边界（RTB）+ 少量机动库”让 AI 飞机看起来像在执行战术，而不是像自动瞄准炮台。**

#### 7.3.1 飞机状态机（SEARCH/FOCUS/ATTACK/DISENGAGE/RTB）

- SEARCH（搜索）
  - 没目标：轻微随机航向偏置，维持较安全姿态
  - 有目标：切换到 FOCUS

- FOCUS（对准/稳定）
  - 关键目标：让机头朝向目标并保持一小段稳定时间
  - 对空：要求“稳定对准窗口”更严格（否则容易抖动乱打）
  - 对地：可以更快进入 ATTACK（因为对地通常就是俯冲航线）

- ATTACK（攻击）
  - 对空：进入 dogfight 时可能启用机动动作（见 7.3.3）
  - 对地：更强调“强制俯冲形成攻击航线”，并允许射击

- DISENGAGE（脱离）
  - 目标：不要无限贴脸缠斗；攻击一段时间后必须拉开再重新进入
  - 行为：朝“远离目标最近位置”的方向飞一段，并调整为较平稳姿态

- RTB（返航）
  - 关键设计：以“起飞点/生成点”为原点设置一个边界；超出边界就强制回到原点附近再继续搜索
  - 这能显著减少 AI 飞机越打越远、飞到世界尽头的问题

#### 7.3.2 起飞/高空行为：避免“天上飘着不下来”

固定翼很容易出现两种糟糕体验：
- 永远在高空盘旋，玩家感觉打不到
- 低空贴地乱撞，玩家感觉像 bug

MCH 的解决思路是做“软约束”：
- 起飞阶段：用“更强的加速/更固定的俯仰”把飞机拉到安全高度
- 高空阶段：触发“周期性俯冲动作”迫使它下高度，增加交战概率
- 对地攻击：当判定为对地目标时，强制进入俯冲航线（否则对地武器很难命中）

#### 7.3.3 Dogfight 机动库（不追求物理真实，只追求可读性）

MCH 的机动动作本质是：在目标 yaw/pitch 的基础上叠加一个“机动偏置”，并在一段时间后切换，形成可读的战斗节奏：

- ORBIT：绕目标转圈（增加侧向机动，让追踪更像缠斗）
- EXTEND：大角度脱离再拉回（避免贴脸无限转）
- BREAK TURN：大幅转向 + 暂时禁止开火（模拟防御动作）
- YOYO HIGH：抬头/拉高再压下（让能量变化看起来更像飞行）

这些动作不需要更多参数：只需要“持续一段时间 + 一个方向（左/右）+ 一个强度档位（小/中/大）”。

#### 7.3.4 导航优先时的策略

当存在“导航优先”：
- 直接把 desiredYaw 指向 waypoint 的 XZ
- desiredPitch 维持平稳
- 禁止开火

这样玩家能理解为“AI 在执行飞行任务，而不是一边走航线一边乱开火”。

**伪代码（非 MCH 原代码，仅表达思想）**：

```text
[PLANE-PILOT-LOOP]
if destroyed or no fuel:
  stop controls, forbid fire
  return

if not originSet:
  origin = currentPositionXZ

if distanceXZ(current, origin) too far:
  state = RTB

if state == RTB:
  desiredYaw = yawTo(origin)
  desiredPitch = stableCruisePitch()
  throttleUp = true
  forbid fire
  if near origin:
    state = SEARCH

else:
  state = updatePlaneStateMachine(targetExists, aimStableWindow)

  desiredYaw = yawTo(target) + maneuverYawBias(state, maneuverMode)
  desiredPitch = pitchTo(target) adjusted by (takeoff/high-altitude/ground-attack heuristics)

  if nav.active and nav.preferNavigate:
    desiredYaw = yawTo(nav.posXZ)
    desiredPitch = stableCruisePitch()
    forbid fire

applyYawSmoothingToward(desiredYaw)
applyPitchSmoothingToward(desiredPitch)
applyThrottlePolicy(state, takeoffPhase, disengagePhase)
```

#### 7.3.5 接战/脱战细化：FOCUS 稳定瞄准 → ATTACK 打一轮 → DISENGAGE 拉开 → 再进场

固定翼的“像人一样”的关键在于：**必须有脱战**。否则就会变成无限小半径转圈贴脸，既不真实也不好玩。

MCH 的节奏要点：

- SEARCH → FOCUS：发现目标进入对准阶段，但不开火
- FOCUS：对空目标要求更严格的“瞄准稳定”才能进 ATTACK；对地目标更快进 ATTACK（因为俯冲航线更重要）
- ATTACK：允许开火，持续一段时间；对空会进入 dogfightEngaged 并启用机动库；对地会强制俯冲姿态
- DISENGAGE：明确朝“远离 lastTarget”方向飞，且 pitch 偏平（更像加速拉开）
- 之后回 SEARCH，重新进入下一轮接战

`autoUseCountermeasures(ac)` 每 5 tick 检查是否存在来袭制导弹药：

- 若 bullet 的 `targetEntity` 指向本机或本机座位，则认为有威胁
- 满足条件时自动使用：
  - flare（优先 type=10）
  - chaff
  - ECM jammer
  - APS

移植建议：
- “威胁判定”不要依赖客户端提示，最好在服务端根据弹药实体状态判断
- 将反制动作做 cooldown（当前是 30 tick）避免刷屏与浪费

## 11. 移植到另一个 mod：推荐的模块拆分

### 11.1 必要模块（最小可用）

- `GunnerEntity`：可挂载到载具/座位的 AI 实体
- `MountSystem`：座位/载具提供：
  - 当前武器集
  - 发射接口（WeaponParam）
  - 载具控制输入（油门/转向/俯仰）
- `Targeting`：
  - 目标类型过滤
  - 可见性/扇区/俯仰约束
  - 节流刷新
- `WeaponSelection`：按上下文与权重选择武器

### 11.2 推荐模块（让玩法更像 MCH）

- `ProfileSystem`：文本/JSON 配置，提供阵营、范围、武器优先级、短点射、愚蠢概率
- `CountermeasureAI`：基于弹药实体/锁定状态判断来袭并自动反制
- `PilotAI`：至少为“地面载具/直升机/飞机”各做一套基础状态机
- `RWR/Radar Integration`：把 AI 锁定也写入威胁输入

## 12. 常见坑点

- 性能：索敌不要每 tick 全量扫，至少要有 5~10 tick 节流；并且先范围过滤再做视线检测。
- 权限：拆除逻辑要与 owner/team 对齐，否则 PVP 里容易被“随手拆队友 AI”破坏体验。
- 武器接口：AI 不应直接 new 弹药实体，应该通过载具的统一武器系统发射（便于热量/弹药/延迟统一）。
- 飞行 AI：没有 RTB 半径约束的飞机很容易飞到世界尽头；没有 AGL 控制的直升机容易飘天。
