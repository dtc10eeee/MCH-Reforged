# Gunner 实体碰撞箱视线检测 — 实施计划

## 1. 背景与现状

### 当前问题

Gunner（AI 炮手）在索敌和攻击时使用 Minecraft 原生的 `canEntityBeSeen()` 方法做视线判定。该方法只检测**方块碰撞**（`worldObj.rayTraceBlocks`），不检测载具/实体的碰撞箱。导致：

- Gunner 可以隔着其他坦克、飞机、车辆射击目标
- 只要目标在山体/建筑方块之外，中间有任何载具实体都不算阻挡
- 缺乏实战中"被载具挡住视线"的自然交互

### 根本原因

`canEntityBeSeen` 是 EntityLivingBase 的方法，内部只调用 `worldObj.func_147447_a()`（纯方块射线追踪），不评估实体包围盒。

`MCH_EntityAircraft` 在构造时将 `boundingBox` 替换为 `MCH_AircraftBoundingBox` 实例（[第 314 行](../src/main/java/mcheli/aircraft/MCH_EntityAircraft.java#L314)），后者覆盖了 `calculateIntercept()` 方法，自动处理旋转炮塔等 OBB 部件——这意味着 `entity.boundingBox.calculateIntercept()` 已经可以精确检测载具碰撞，只差被 Gunner 的视线检查调用。

## 2. Phase 1：工具函数 — `MCH_RayTracer.hasBlockingEntity`

**文件：** `src/main/java/mcheli/MCH_RayTracer.java`

新增静态方法：

```java
public static boolean hasBlockingEntity(
    World world,
    Vec3 start,
    Vec3 end,
    Entity excludeSelf,
    Entity excludeTarget,
    Class<? extends Entity> scanClass,
    double maxRange
)
```

### 参数说明

| 参数 | 类型 | 说明 |
|------|------|------|
| `world` | World | 世界对象 |
| `start` | Vec3 | 射线起点（Gunner 眼睛位置） |
| `end` | Vec3 | 射线终点（目标中心位置） |
| `excludeSelf` | Entity | 排除自己的载具（不遮挡自身） |
| `excludeTarget` | Entity | 排除目标实体本身 |
| `scanClass` | Class<? extends Entity> | 扫描的实体类型（默认 `MCH_EntityAircraft.class`） |
| `maxRange` | double | 最大检测距离，超过直接返回 false |

### 逻辑

```
1. 计算 start→end 向量，距离 > maxRange 则直接返回 false

2. 以 start 为中心构造包含整条线段的 AABB：
   aabb = AxisAlignedBB.getBoundingBox(
       min(start.x, end.x), min(start.y, end.y), min(start.z, end.z),
       max(start.x, end.x), max(start.y, end.y), max(start.z, end.z)
   )

3. worldObj.getEntitiesWithinAABB(scanClass, aabb)

4. 对每个候选 entity：
   a. entity == excludeSelf → 跳过
   b. entity == excludeTarget → 跳过
   c. entity.isDead → 跳过
   d. 检查 entity.ridingEntity 链是否包含 excludeSelf → 跳过（同载具座位不遮挡）
   e. entity.boundingBox.calculateIntercept(start, end) != null
      → 射线穿过此载具 → 返回 true

5. 无命中 → 返回 false
```

### 性能考虑

- `scanClass` 限定为 `MCH_EntityAircraft.class`，只检测 MCH 载具，不检测玩家/生物/FMUR
- `maxRange` 默认 500m，超过不做实体检测
- `getEntitiesWithinAABB` 在 1.7.10 中按类型索引，开销可控

## 3. Phase 2：Gunner 索敌链路注入

**文件：** `src/main/java/mcheli/mob/MCH_EntityGunner.java`

### 3a. 辅助方法 — `getGunnerEyePos`

```java
private Vec3 getGunnerEyePos(MCH_EntityAircraft ac, MCH_WeaponSet ws, Vec3 weaponPos) {
    if (ws != null && ws.getCurrentWeapon() != null) {
        return Vec3.createVectorHelper(weaponPos.xCoord, weaponPos.yCoord + 1.5D, weaponPos.zCoord);
    }
    return Vec3.createVectorHelper(posX, posY + (double)getEyeHeight(), posZ);
}
```

使用武器发射口位置 + 1.5m 作为眼睛位置（炮塔观察位），fallback 到 gunner 自身眼睛位置。

### 3b. 索敌阶段 — `updateTargetForWeapon`

**位置：** 第 904 行附近

在当前 `canEntityBeSeen(entity)` 之后注入实体遮挡检测：

```java
// 现有代码
if (canAttackEntity(entity, ac, ws))
    if ((heliPilot || planePilot || checkPitch(entity, ac, pos)))
        if (canEntityBeSeen((Entity)entity))              // ← 现有：方块检查
            // ... 后续处理
```

改为：

```java
if (canAttackEntity(entity, ac, ws))
    if ((heliPilot || planePilot || checkPitch(entity, ac, pos)))
        if (canEntityBeSeen((Entity)entity)) {              // ← 方块检查
            if (MCH_Config.GunnerEnableEntityLosCheck.prmBool      // ← 配置开关
                && MCH_RayTracer.hasBlockingEntity(
                    worldObj,
                    getGunnerEyePos(ac, ws, pos),           // ← 眼睛位置
                    Vec3.createVectorHelper(
                        entity.posX,
                        entity.posY + entity.height / 2.0D,
                        entity.posZ),                       // ← 目标中心
                    ac,                                     // ← 排除自己载具
                    entity,                                 // ← 排除目标本身
                    net.minecraft.entity.Entity.class,      // ← 扫描所有实体
                    500.0D)) {                               // ← 500m 上限
                continue;                                   // ← 被挡住，跳过
            }
            // ... 现有 isInAttackable 等后续逻辑
        }
```

**注意：** `scanClass` 用 `Entity.class` 而不是 `MCH_EntityAircraft.class`，因为需要检测所有类型的实体（包括其他载具、FMUR 实体等）。`excludeSelf` 和 `excludeTarget` 负责排除不相关的实体。如果性能敏感可改回 `MCH_EntityAircraft.class`。

### 3c. 攻击阶段 — `shotTarget`

**位置：** 第 503 行附近

`shotTarget` 每 tick 调用 `updateTargetForWeapon()` 重新确认目标。3b 的改动自动作用于持续攻击——目标被其他载具挡住后，下个 tick 就会因为不通过 `canEntityBeSeen + hasBlockingEntity` 双检查而被跳过，Gunner 会切换目标或停止开火。

无需额外改动。

## 4. Phase 3：配置控制

**文件：** `src/main/java/mcheli/MCH_Config.java`

```java
public static MCH_ConfigPrm GunnerEnableEntityLosCheck = new MCH_ConfigPrm("GunnerEnableEntityLosCheck", "true");
```

在配置初始化块中注册（参照其他配置项的模式）：

```java
// 在 load() 方法的适当位置
GunnerEnableEntityLosCheck.prmBool = GunnerEnableEntityLosCheck.getBoolean(enableEntityLosCheck);
```

**配置效果：**

| 值 | 行为 |
|----|------|
| `true`（默认） | Gunner 索敌时检测中间实体碰撞箱，被遮挡的不锁定 |
| `false` | 退回原行为，只检测方块遮挡，不检测实体 |

## 5. 数据流图

```
onUpdate_Server()
  │
  └─ [坦克/直升机/飞机分支]
       │
       ├─ updateTargetForWeapon(ac, ws, pos)
       │    │
       │    ├─ worldObj.getEntitiesWithinAABB(EntityLivingBase, AABB)
       │    │
       │    └─ for each candidate:
       │         ├─ targetType + team 过滤
       │         ├─ isPlaneAirTarget / canAttackEntity
       │         ├─ checkPitch (俯仰角)
       │         ├─ canEntityBeSeen (方块视线)          ← 现有
       │         ├─ [新增] hasBlockingEntity (实体视线)  ← Phase 2
       │         │    ├─ MCH_Config.GunnerEnableEntityLosCheck ? : 跳过
       │         │    ├─ getGunnerEyePos(ac, ws, pos)
       │         │    └─ entity.boundingBox.calculateIntercept(start, end)
       │         ├─ isInAttackable (偏航角)
       │         └─ 选最近 → targetEntity
       │
       └─ shotTarget(ac)
            └─ updateTargetForWeapon() 每 tick 重新确认 ← 自动生效
```

## 7. 测试清单

1. **Gunner 在 Tank A 上，Tank B 在 Gunner 和目标之间**
   - 预期：Gunner 不锁定目标（被 Tank B 挡住）
   - 方法：用创造模式放置三台坦克成直线排列

2. **Tank B 移开后**
   - 预期：Gunner 重新锁定并攻击目标
   - 方法：移除中间的 Tank B

3. **目标本身是 Tank C**
   - 预期：目标本身不被视为遮挡
   - 方法：Gunner 直接面对 Tank C，中间无其他载具

4. **同载具不同座位**
   - 预期：同载具的其他座位不视为遮挡
   - 方法：Gunner 在 Seat 2，Seat 1 有玩家，Seat 3 空

5. **配置开关 `GunnerEnableEntityLosCheck=false`**
   - 预期：退回原行为，不检测实体遮挡
   - 方法：修改配置后重启

6. **方块遮挡仍然生效**
   - 预期：目标在山体后依然不能锁定
   - 方法：目标在山体背面
