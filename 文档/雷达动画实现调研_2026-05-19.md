## 1. “雷达动画”由哪些模块组成

### 1.1 HUD 雷达面板（屏幕上的扫描动画）

HUD 雷达面板逻辑集中在 [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java)：

- 目标点渲染（点大小、选中/跟踪高亮、速度向量）

- `MCH_RenderAircraft.renderRadarDisplayPart` 在渲染模型时对 `$radardisplay` 进行两次绘制：
  1) 先画纯黑底（完全不采样原机体贴图 alpha）

见 [MCH_RenderAircraft.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/aircraft/MCH_RenderAircraft.java#L1529-L1574)。

## 2. 扫描线动画：如何从 tick 得到“扫掠相位”

### 2.1 统一的相位定义（HUD 与座舱共用）

雷达扫掠相位 `phase` 的基础定义是：

- `scanTick = max(1, RadarScanTick)`
- `phase = ((worldTick % usedScanTick) + partialTicks) / usedScanTick`
- `usedScanTick = scanTick`（常规）或 `scanTick/4`（ACM 加速）

见 [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L3308-L3316)。

这个 `phase ∈ [0,1)` 是“动画时间轴”，**决定扫掠线当前角度**，同时也用于动态贴图的更新节奏（见第 4 节）。

### 2.2 扫掠角：全圆 vs 扇区（Ping-Pong）

扫掠线角度计算分两类：

1) **全圆扫描**（`RadarScanAzimuthDeg >= 360`）
- 扫掠线连续绕圈：
  - `sweepDeg = axisDeg + phase * 360`

2) **扇区扫描**（`RadarScanAzimuthDeg < 360`）
- 采用 Ping-Pong 来模拟“左右往返”：
  - `p = clamp(phase, 0..1)`
  - `pingPong = p<=0.5 ? (p*2) : (2 - p*2)`  → 映射到 `[0..1..0]`
  - `sweepDeg = startDeg + scanAz * pingPong`

座舱雷达贴图的实现可直接对照：
- [MCH_RadarDisplayTextureManager.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RadarDisplayTextureManager.java#L149-L187)

HUD 绘制扇区/扫掠线对应：
- `drawRadarScanSkeleton(...)` 里选择 circle/sector 分支并画 sweep line
- [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L1038-L1056)

### 2.3 轴向与跟随炮塔

当前 enableRadar 面板默认让雷达面板“屏幕固定朝向”，基础轴向为：

- `axisDeg = -90`

见 [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L875-L878) 与 [buildRadarDisplayFrame](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L3357-L3360)。

坦克可选启用 `RadarFollowTurretYaw`，在投影与扫描范围判定时会参考炮塔偏航（影响点位投影与可见性），见 `followTurretYaw` 参数贯穿投影函数调用链。

## 3. 目标点“闪烁/保持/消失”：接触缓存（这也是动画的一部分）

雷达点的显示不是每帧从零计算“立即可见”，而是有一个**接触缓存**（contact cache）：

- `radarContactCache: Map<aircraftId, Map<targetId, RadarContact>>`
- 每个 contact 有 `ttl`（剩余显示 tick）
- 每 tick 根据世界时间衰减 `ttl`，到 0 就移除

见：
- `decayRadarContactsStatic` [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L1636-L1658)

### 3.1 刷新节奏：每 scanTick 一个“扫描槽位”

雷达接触刷新不是每帧执行，而是以“扫描槽位（slot）”为粒度：

- `slot = worldTick / scanTick`
- 同一 slot 内只刷新一次（用 `radarLastScanSlot` 记忆）

见 [refreshRadarContactsStatic](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L1775-L1784)。

这会导致一个直观效果：
- `RadarScanTick` 越大 → 新点出现得越慢、旧点在 holdTick 内“拖影”更明显
- `RadarContactHoldTick` 越小 → 点闪烁更明显（TTL 更快耗尽）

### 3.2 命中概率：让接触“有噪声”

刷新时会计算一个基础探测概率与距离增益（近强远弱）：

- `radarDetectChanceBase`
- `radarGainNearFactor / radarGainFarFactor`

见 [refreshRadarContactsStatic](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L1795-L1800)。

这会带来“点在某些周期里没刷到”的现象：看起来像点在闪烁（实际上是缓存 TTL + 概率刷新共同作用）。

### 3.3 TTL（保持时间）

接触保持时间来自配置：

- `RadarContactHoldTick`

刷新时会给命中的 contact 设置/续期 TTL，衰减逻辑负责逐步移除（参考 3.0）。

## 4. 座舱雷达屏动画：动态贴图如何生成与更新

### 4.1 贴图生成流程

`MCH_RadarDisplayTextureManager.getTexture(ac, player, partialTicks)` 的主要流程：

1) 为每架载具创建并缓存一张 `DynamicTexture(256x256)` 与 `pixels[]`
2) 首次会分块清空像素（warmup）以降低卡顿
3) 若载机 `jammingTick > 0`，直接返回“共享干扰贴图”
4) 其余情况调用 `MCH_RenderRWR.buildRadarDisplayFrame(...)` 构建一帧的“雷达显示帧”
5) 用 `renderGraphicsFrame(pixels, frame, color)` 画扫掠线/扇区/点/链接线
6) 用 `renderTextLayer(textPixels, frame, color)` 画文字（低频更新，5 tick 一次或 hash 改变）
7) 合成并 `updateDynamicTexture()` 上传

见 [MCH_RadarDisplayTextureManager.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RadarDisplayTextureManager.java#L22-L74)。

### 4.2 更新节流：相位桶 + 锁定强制更新

为了避免每帧都重绘贴图，采用了“相位桶”：

- `phaseKey = worldTick*4 + bucket(partialTicks*4)`，也就是每 tick 最多 4 桶
- 若没有锁定（trackingTargetId <= 0），并且 phaseKey 没变，就直接返回缓存贴图

见 [MCH_RadarDisplayTextureManager.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RadarDisplayTextureManager.java#L41-L52)。

这会让座舱雷达屏动画看起来比 HUD 稍“低帧率”，但换来显著的性能收益。

## 5. ACM 模式的动画差异

在 HUD 与座舱两侧，ACM（近距空战）模式都会：

- 扫描周期加速：`usedScanTick = scanTick/4`
- 扫描扇区变窄：默认 `5 deg`
- 扫掠轴向可跟随鼠标偏移（类似“机头视线中心偏置”）

HUD 侧：
- `drawAcmRadarSectorOverlay(...)` 画窄扇区与其扫掠线
- `drawAcmScanOverlay(...)` 在准星附近画一个扫描框提示

见 HUD 调用点 [MCH_RenderRWR.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderRWR.java#L923-L926)。

座舱贴图侧：
- `renderGraphicsFrame` 在 `frame.acmMode` 下会额外画 ACM 扇区与扫掠线

见 [MCH_RadarDisplayTextureManager.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RadarDisplayTextureManager.java#L189-L211)。

## 7. 关键配置项速查（影响动画观感）

载具配置（`MCH_AircraftInfo`）中与动画强相关的字段：

- `EnableRadar`：总开关
- `RadarScanAzimuthDeg`：水平扫描扇区角（360=全圆；<360=扇区往返）
- `RadarScanTick`：扫描周期 tick（影响扫掠速度 & 接触刷新粒度）
- `RadarPanelFillAlpha`：扇区填充透明度（HUD & 座舱贴图）
- `RadarContactHoldTick`：接触保持 tick（影响点“闪烁/拖影”）
- `RadarSearchType`：SRC/TWS/GMTI/...（决定过滤与跟踪显示逻辑，也间接影响点的出现）
- `RadarMaxTargetRange`：最大显示距离（影响点的归一化与出现）
- `RadarFollowTurretYaw`：坦克雷达朝向是否跟随炮塔
- `RadarScanElevationDeg / RadarElevationReference / RadarElevationCoverage`：俯仰扫描范围（影响目标是否被投影/过滤）

解析入口参考：[MCH_AircraftInfo.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/aircraft/MCH_AircraftInfo.java#L972-L1050)
