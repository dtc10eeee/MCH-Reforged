# GPS 导弹实现思想与复用指南（基于 MCH-Reforged）

目标：梳理当前 MCH-Reforged 的 GPS/坐标制导导弹实现思路，给其他 mod 复用时提供清晰的“数据流 + 状态机 + 同步方式 + 关键参数”参考。

本文只描述思想与接口形态，不要求其他 mod 使用完全相同的类结构。

---

## 1. 总览：MCH 的 GPS 导弹是什么

在当前实现里，“GPS 导弹”不是单独一种全新的武器类型，它是：

- 武器类型仍是 **ASMissile（空对地导弹）**；
- 通过武器配置项 `IsGPSMissile=true` 启用“坐标制导”逻辑；
- 目标点来自 **客户端选点**（HUD/锁定动作/GUI 输入），并通过网络同步到服务端；
- 发射时服务端将“目标坐标”写进导弹实体的 `originTargetPosX/Y/Z`；
- 导弹飞行过程中每 tick 根据目标点调用通用制导函数 `guidanceToPos(...)` 或带巡航的 `guidanceToPosWithCruise(...)`；
- 可选启用“弹道导弹式抛物线/侧向蛇形”目标点计算（`BallisticMissile=true`）；
- 到达目标点附近后可选择“释放制导”（`gpsGuidanceReleased`），让导弹不再继续修正。

关键代码入口：
- 选点与发射端：`MCH_WeaponASMissile` [MCH_WeaponASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponASMissile.java)
- GPS 位置存储与同步：`MCH_GPSPosition` [MCH_GPSPosition.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_GPSPosition.java) + [PacketGPSPositionReset.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/network/packets/PacketGPSPositionReset.java)
- 导弹实体与制导/弹道：`MCH_EntityASMissile` [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java)
- 通用制导/巡航：`MCH_EntityBaseBullet` [MCH_EntityBaseBullet.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityBaseBullet.java)
- HUD 标记渲染：`MCH_RenderGPSPosition` [MCH_RenderGPSPosition.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderGPSPosition.java)

## 2. 数据结构与字段含义

### 2.1 GPS “目标点”存储（按玩家）

`MCH_GPSPosition` 维护两份状态：

- 客户端：`currentClientGPSPosition`（仅用于 HUD 显示和本地输入回显）
- 服务端：`currentGPSPositions: Map<playerEntityId, MCH_GPSPosition>`（用于发射时取目标点）

见 [MCH_GPSPosition.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_GPSPosition.java)

字段：
- `x/y/z`：目标点坐标（世界坐标）
- `isActive`：是否有效（当前实现只检查 true/false）
- `owner`：拥有者（服务端包处理处设置为 `playerEntity`）

网络同步：
- 客户端调用 `MCH_GPSPosition.set(...)` 时，会发送 `PacketGPSPositionReset` 给服务端；
- 服务端在包回调 `handleServerSide` 里把该点写入 `currentGPSPositions`。

见 [PacketGPSPositionReset.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/network/packets/PacketGPSPositionReset.java#L47-L53)

### 2.2 导弹实体的目标点字段

`MCH_EntityASMissile` 内关键字段：
- `targetPosX/Y/Z`：当前用于制导的目标点（可能随时间更新）
- `originTargetPosX/Y/Z`：发射瞬间/初始 GPS 目标点（通常不变，用于“GPS 释放制导判定”、以及某些模式下的锚点）
- `targeting`：是否正在制导（tick 内若 false 会停止调用 guidance）
- `gpsGuidanceReleased`：GPS 导弹到达目标附近后是否已释放制导（释放后 tick 直接 return）
- `cruiseMode`：是否启用巡航逻辑（高度保持/末段转入）
- `launchPosX/Y/Z` + `launchPosInitialized`：弹道模式用的发射点
- `ballisticProgress`：弹道模式中用于保证“进度 u 单调”的变量（避免回头）

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java)

## 3. 端到端数据流（客户端选点 → 服务端发射 → 导弹制导）

### 3.1 客户端如何“选 GPS 点”

实现提供两条入口（可并存）：

1) 通过武器“锁定流程”触发选点
- `MCH_WeaponASMissile.lock()` 在客户端计时到 `weaponInfo.lockTime` 后调用 `clientLock(prm)`
- `clientLock(prm)` 会按视线做分段 raytrace（1500m/100m 一段），取第一个命中的方块面或默认远端点
- 然后 `MCH_GPSPosition.set(hitVec, true, prm.user)` → 发送包到服务端

见 [MCH_WeaponASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponASMissile.java#L208-L267)

2) 通过 GUI 直接输入坐标
- `MCH_GuiGPSInput` 允许输入 X/Y/Z 并调用 `MCH_GPSPosition.set(x,y,z,true,player)`

见 [MCH_GuiGPSInput.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/gui/MCH_GuiGPSInput.java#L119-L136)

HUD 显示：
- `MCH_RenderGPSPosition` 在“玩家正驾驶且当前武器是 GPS 导弹上下文”时渲染一个世界空间标记

见 [MCH_RenderGPSPosition.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/render/MCH_RenderGPSPosition.java#L183-L193)

### 3.2 服务端如何“拿到目标点”

服务端并不主动计算选点，它只接收：
- `PacketGPSPositionReset`（携带 x/y/z/isActive/ownerId）

并在 `handleServerSide(EntityPlayerMP playerEntity)` 中写入：
- `MCH_GPSPosition.currentGPSPositions.put(playerEntity.getEntityId(), gpsPosition)`

见 [PacketGPSPositionReset.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/network/packets/PacketGPSPositionReset.java#L47-L53)

### 3.3 发射时如何把目标点写进导弹

发射端在服务端执行（`worldObj.isRemote == false`）：

- 创建 `MCH_EntityASMissile`
- 优先级分配目标：
  1) gunner 指定实体（`prm.user instanceof MCH_EntityGunner`）
  2) 玩家 GPS 点（`MCH_GPSPosition.get(prm.user)` 且 `isActive`）
  3) 退回到实体锁定目标（`tgtEnt`）
- 写入：
  - `missile.targetPosX/Y/Z`
  - `missile.originTargetPosX/Y/Z`
  - `missile.targeting = true`
- 同时设置 `missile.cruiseMode = (mode==1) && armCruiseEnable`

见 [MCH_WeaponASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponASMissile.java#L108-L147)

此外还有一个“工厂型”入口：
- `MCH_WeaponCreator.setEntityInfo()` 也会在 `asMissile + isGPSMissile` 时，把玩家 GPS 点写入导弹实体

见 [MCH_WeaponCreator.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponCreator.java#L54-L82)

## 4. 导弹飞行状态机（MCH_EntityASMissile）

导弹飞行每 tick 主要流程（服务端）：

1) 初始化发射点（用于弹道模式）
- 首次 `onUpdate()` 将当前位置写入 `launchPosX/Y/Z`

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L52-L60)

2) 失效与距离裁剪
- 距离发射者过远（>2000m）直接 `setDead()`

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L65-L72)

3) 刚体时间后开始制导
- `getCountOnUpdate() > rigidityTime` 后才进入制导段

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L73-L114)

4) GPS 释放制导（可选）
- 当 `isGPSMissile && !lockEntity` 且导弹距离 `originTargetPos` 小于等于 5 格（平方距离 25）
- 设置：
  - `gpsGuidanceReleased = true`
  - `targeting = false`
- 后续 tick 直接 return（不再修正）

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L74-L85)

5) 目标点选择与制导调用

两种模式：

- `lockEntity == true`：在目标点附近搜索实体（当前实现偏向搜索 `MCH_EntityAircraft`）
  - 若发现实体在 `maxLockOnRange` 内，则刷新 `targetPosX/Y/Z = entity.pos`
  - 之后对 `targetPos` 做弹道/巡航制导

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L86-L105)

- `lockEntity == false`：直接对 `originTargetPos` 制导（更符合“纯 GPS 坐标攻击”）

见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L106-L112)

制导函数来自基类：
- `guidanceToPos(tx,ty,tz)`：带最大偏角限制与 turningFactor 平滑
- `guidanceToPosWithCruise(tx,ty,tz)`：若满足巡航条件则先保持高度（`guidanceToPos(tx, posY, tz)`）

见 [MCH_EntityBaseBullet.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityBaseBullet.java#L719-L779)

## 5. “弹道 GPS 导弹”思想（BallisticMissile）

当满足：
- `isGPSMissile == true`
- `ballisticMissile == true`
- `launchPosInitialized == true`

导弹不会直接把目标点作为制导点，而是通过 `computeBallisticAimPoint(...)` 计算一个“临时瞄点”，再去制导这个瞄点。

见 [computeBallisticAimPoint](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L146-L212)

核心思想：
- 用发射点 `launchPos` 与目标点 `targetPos` 的水平距离决定“拱高”：
  - `arcHeight = clamp(ballisticArcMinHeight, horizontalTotal*ballisticArcFactor, ballisticArcMaxHeight)`
  - `aimY = targetY + 4*u*(1-u)*arcHeight`（标准抛物线顶点在 u=0.5）
- 进度参数 `u` 的计算是“沿地面航迹的投影比例”，并强制单调不减：
  - `uRaw = dot(relNow, total) / |total|^2`
  - `u = clamp(uRaw, 0..1)`
  - `u = max(u, ballisticProgress)`，并更新 `ballisticProgress = u`
  - 目的：导弹即便受扰动/机动，也不会因为投影回退导致“瞄点跑到发射点方向”，从而出现掉头。
- 横向蛇形（可选）：在 `u` 区间内施加沿法向的正弦偏移，末段抑制：
  - 法向：`n = (-totalZ, totalX) / horizontalTotal`
  - `offset = amplitude * sin(2π*waves*u + phase) * sin(π*t)`（t 为 u 在区间内的归一化）
  - 当进入终端近距离/终端圆柱区域时，强制关蛇形并把 `aimY` 收敛回 `targetY`，避免末段上抬偏差。

建议其他 mod 复用时保留的优点：
- “瞄点随 u 单调推进”的设计能显著减少导弹掉头/抽搐；
- 弹道拱高只改 Y，不改变水平锁定在目标点（避免水平漂移导致完全打偏）；
- 终端抑制蛇形能提升命中稳定性。

## 6. 配置项（给其他 mod 的接口建议）

MCH 的武器配置由 `MCH_WeaponInfo` 解析。以下是与 GPS 相关的关键项（名字区分大小写不敏感）：

- `IsGPSMissile`：是否启用 GPS/坐标制导
- `BallisticMissile`：是否启用弹道瞄点
- `BallisticArcFactor / BallisticArcMinHeight / BallisticArcMaxHeight / BallisticMinDistance`
- `BallisticLateralSine` 与其参数：
  - `BallisticLateralAmplitude`
  - `BallisticLateralWaves`
  - `BallisticLateralPhaseDeg`
  - `BallisticLateralStartRatio / BallisticLateralEndRatio`
  - `BallisticTerminalNoWeaveDist / BallisticTerminalCylinderRadius`
- `ArmCruiseEnable` 与其参数：
  - `ArmCruiseStartDistance`
  - `ArmCruiseTerminalRadius`
  - `ArmCruiseTerminalHeight`
- 通用制导相关：
  - `TurningFactor`（越小越平滑）
  - `MaxDegreeOfMissile`（每 tick 允许的最大偏角）
  - `RigidityTime`（刚射出不允许转向的 tick）

解析入口（便于对照 key 名）：[MCH_WeaponInfo.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_WeaponInfo.java#L1074-L1130)

## 7. 复用到“另一个 mod”的推荐实现蓝图

### 7.1 最小可用版本（强推荐先做这个）

数据：
- `GpsTarget { double x,y,z; boolean active; }`（按玩家存一份）

客户端：
- 提供一个选点动作：
  - 视线 raytrace 命中点 / 或 GUI 输入坐标
- 选点后发送 `C2S_GpsTargetUpdate(x,y,z,active)` 给服务器
- 本地 HUD 可显示该点（可选）

服务端：
- 收到包后更新 `Map<playerUuid, GpsTarget>`
- 发射 GPS 导弹时读取该点并写入导弹实体：
  - `originTarget = gpsTarget`，`targeting=true`

导弹 tick（服务端）：
- 若 `targeting`，则每 tick 调 `guidanceToPos(target)`
- 可选：距离目标 < 阈值时释放制导（停止修正）

### 7.2 建议增强项（对标 MCH）

- 巡航模式：远距离保持高度，仅在末段/近距离时再追 y
  - 直接复用 `guidanceToPosWithCruise` 的思想：[MCH_EntityBaseBullet.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityBaseBullet.java#L756-L779)
- 弹道瞄点：复用 `computeBallisticAimPoint` 的 u 单调推进 + 抛物线拱高 + 终端抑制蛇形
  - 见 [MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java#L146-L212)
- 多目标/动态目标（可选）：以 `originTarget` 作为锚点，在一定范围内搜索可攻击实体并转换为末制导

## 8. 坑点与注意事项（其他 mod 最常踩）

- 客户端选点必须防作弊：服务端可加校验（例如：最大距离、是否在可见/已加载区域、是否允许隔墙指定）。
- 坐标目标需要生命周期管理：MCH 里 `currentGPSPositions` 不自动过期；其他 mod 建议：
  - 在玩家死亡/下线清理
  - 或加 TTL（例如 30s）
- 世界维度：若跨维度，要把维度 id 一并同步与验证。
- Chunk 加载：GPS 导弹可能飞向未加载区块；若你的导弹碰撞/爆炸需要服务端计算，可能需要区块加载策略。
- 命中判定与释放制导：释放阈值（MCH 用 5 格）过大可能早停导致偏差；过小可能来回修正引起摆动。
- turningFactor 与 maxDegree：过大导弹会“急转抽搐”，过小可能拐不过去；建议做随时间变化的 turningFactor（MCH 有 `initTurningFactorTick` 系列参数）。

## 9. 对照清单（实现完成度自检）

- 客户端：能选点（raytrace/GUI）并能看到当前 GPS 点（可选）
- 网络：C2S 包能可靠更新服务端玩家 GPS 点
- 发射：服务端发射时把 `originTargetPos` 写入导弹
- 导弹：服务端 tick 能持续调用制导，并在需要时释放制导
- 参数：能配置 turningFactor/maxDegree/rigidityTime；可选巡航与弹道参数
